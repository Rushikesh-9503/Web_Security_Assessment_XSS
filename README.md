# From Stored XSS to a Self-Propagating XSS Worm

## Web Security Assessment of a Deliberately Vulnerable Elgg Application

A practical web security assessment conducted as part of my MSc Cyber Security studies in a controlled SEED/Elgg laboratory environment.

## Overview

This project investigates how a stored Cross-Site Scripting (XSS) vulnerability can progress from a basic JavaScript execution proof of concept to a self-propagating XSS worm.

The assessment was performed against a deliberately vulnerable Elgg web application and followed a progressive attack methodology:

```text
Stored XSS
    ↓
HTTP Request Analysis
    ↓
Authenticated Action
    ↓
Profile Modification
    ↓
Self-Propagation
```

The assessment demonstrates both offensive web security techniques and the investigative perspective required to understand the resulting activity.

## Objectives

* Identify and validate a stored XSS vulnerability.
* Demonstrate JavaScript execution within another authenticated user's browser.
* Analyse legitimate HTTP requests generated by the application.
* Reproduce authenticated application actions using JavaScript.
* Demonstrate unauthorised profile modification.
* Develop and test a self-propagating XSS payload.
* Observe propagation between controlled test accounts.
* Analyse the underlying security weaknesses.
* Recommend appropriate security mitigations.

## Assessment Stages

### 1. Stored XSS Proof of Concept

A JavaScript payload was injected into a profile field and stored by the application. When another authenticated test account viewed the infected profile, the JavaScript executed in the browser.

This confirmed the presence of a stored XSS vulnerability.

### 2. HTTP Request Analysis and Authenticated Action

A legitimate Add Friend operation was captured and analysed using HTTP request monitoring.

The request structure and required parameters were examined before reproducing the application action through JavaScript executed within the victim's browser.

### 3. Unauthorised Profile Modification

The profile-edit functionality was investigated and its legitimate HTTP request was analysed.

A JavaScript payload was then used to submit a profile modification request that changed the victim's profile description to:

> "Samy is my hero"

This demonstrated that stored XSS could be used to perform an authenticated state-changing action.

### 4. Self-Propagating XSS Worm

The final stage extended the attack by removing the hard-coded victim and dynamically identifying the currently authenticated user.

The payload was also designed to retrieve and replicate its own script content.

Testing demonstrated propagation between controlled laboratory accounts.

Observed propagation:

```text
Samy → Alice → Boby
```

## Security Recommendations

The assessment identified several defensive controls that can reduce the risk of XSS and related attacks:

* Context-aware output encoding
* Strict HTML sanitisation
* Server-side input validation
* Content Security Policy (CSP)
* Robust CSRF protection for state-changing operations
* Secure session management

These controls should be implemented as complementary layers rather than relying on a single defensive mechanism.
